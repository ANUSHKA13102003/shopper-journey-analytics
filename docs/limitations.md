# Limitations

1. **First-seen is not a true new user**: REES46 covers only 61 days (`2019-10-01` to `2019-11-30`) with no account creation timestamp. Excluding users first seen in the first 7 days reduces contamination from frequent visitors, but infrequent returning shoppers first seen after October 7 are still counted as new.
2. **Two-month window limits long-term retention**: Because the log ends on `2019-11-30`, D28 return can only be measured for users first seen on or before `2019-11-02` (`2,205,364` of `4,359,106` cohort users), and 28-day repeat purchase only covers `274,794` early buyers. November Black Friday seasonality also shifts late-November cohorts.
3. **Missing `remove_from_cart` and unmapped categories**: Although the Kaggle dataset description lists `remove_from_cart`, the Oct-Nov 2019 files contain zero `remove_from_cart` rows. Additionally, `32.21%` of events (`35,413,780` rows) have null `category_code` and are grouped under `'unknown'`.
4. **Criteo features are anonymized**: The 12 covariates (`f0..f11`) in Criteo Uplift v2.1 have no business labels, and 7 of 12 are concentrated at a mode with tied quartiles. We can identify which anonymized slices respond best, but cannot name the underlying user attributes without internal feature mapping.
5. **Part A and Part B come from different companies**: REES46 is multi-category e-commerce clickstream data from 2019, while Criteo Uplift v2.1 is an ad-targeting randomized trial from Criteo. They are combined to show the full analyst workflow (diagnose funnel and retention, then evaluate an ad experiment), not as one unified store.
6. **No real ad cost or margin in Criteo**: Criteo Uplift does not report CPM/CPC or order margin, so the break-even table is an explicit assumptions grid rather than actual P&L.
7. **Download route switch**: `scikit-uplift`'s `fetch_criteo` URL returned HTTP 404 and the direct `go.criteo.net` stream stalled; we switched to the official Hugging Face mirror (`criteo/criteo-uplift`).
